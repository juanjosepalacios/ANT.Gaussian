Atomistic NanoTransport

Installation instructions

Choose your interface: ANT.Gaussian09 installation · ANT.Gaussian16 installation

These instructions describe ANT.Gaussian09 3.3.0. Reviewed against the source repository on 26 November 2026. Local compiler and Gaussian paths must be configured before building.

Requirements

  • A Linux/UNIX build environment with Bash, Make, Git and archive tools.
  • A working, source-built Gaussian09 installation, with its source files, libraries, build tools and g09/make.log available.
  • A compatible Fortran compiler: the current build files provide Intel ifx or NVIDIA/PGI pgf90 configurations. Use a toolchain compatible with your Gaussian build.
  • Intel builds require Intel oneMKL and icx. The default NVIDIA configuration uses the HPC SDK ILP64 BLAS/LAPACK libraries, plus nm and objcopy; a bundled reference-library option is also provided.

1. Get the source

git clone https://github.com/juanjosepalacios/ANT.Gaussian.git
cd ANT.Gaussian
mkdir -p bin obj lib
git rev-parse HEAD

Record the commit with your calculation results. The repository is named ANT.Gaussian; it supplies the ANT.Gaussian09 code.

2. Prepare the Gaussian interface

Load your Gaussian and compiler environments so that gau-cpp, gau-fsplit and set-mflags are available. For Gaussian09 revision D.01, the repository provides install/install.g09.D01. Inspect and edit this script before running it: its g09root and F90 values are examples from the developer’s machine. Here, g09root is the directory containing g09/.

cd install
# Edit install.g09.D01 for your Gaussian installation and compiler.
bash install.g09.D01
cd ../src

The script modifies Gaussian interface sources, builds l101.exe and l103.exe, and prepares ml502.o, l502.a, bdam1.o and caldsu.o in bin/. It also generates src/make.in from Gaussian’s build settings. Check these outputs and the build log before continuing. Other Gaussian revisions may require adjustments to the extraction script; the repository also contains install.g09.1 and install.g09.2, which must be inspected for compatibility.

A failure while attempting to link the intermediate Gaussian l502.exe may occur before ANT itself is linked. Do not ignore errors generally: verify that every required interface object and archive was produced successfully.

3. Select and configure a build

Intel ifx

Edit src/Makefile.intel.g09 and the generated src/make.in. Set MKLROOT, compiler paths, GAUSSLIBS and compiler/linker flags for your machine. make.in.intel is an example configuration, with machine-specific paths.

Keep Gaussian-compatible integer sizes and preprocessor dimensions. The supplied configuration uses -i8 -r8 and MKL’s ILP64 interface. The Makefile documents the need for -fp-speculation=safe in Gaussian’s Intel build (RUNF77 in bsd/i386.make), to avoid failures in Gaussian’s bundled eigensolver and SVD routines. Its MKL DSYEVD link workaround protects the ANT link only; it does not repair other Gaussian executables.

make -f Makefile.intel.g09

The ANT executable is written to bin/l502.exe.

NVIDIA / PGI

Edit src/Makefile.nvidia.g09 and src/make.nvidia.in. Set the compiler, Gaussian library paths, target CPU flags and NVHPCLIB for your installation. The default ANTLAPACK=nvhpc uses renamed HPC SDK ILP64 library symbols to avoid replacing Gaussian’s own BLAS/LAPACK routines. Set ANTLAPACK=bundled to use the bundled reference routines instead.

This Makefile uses BIN=../bin/nvidia. Create that directory and place the matching NVIDIA-built interface products there: ml502.o, l502.a, bdam1.o, caldsu.o, l101.exe and, when needed, l103.exe. The D.01 preparation script writes to bin/, so its products must be placed in the directory selected by the Makefile. Do not mix Intel and NVIDIA objects.

# From src/, after configuring the paths and interface products:
mkdir -p ../bin/nvidia
make -f Makefile.nvidia.g09

The ANT executable is written to bin/nvidia/l502.exe. Build serially: the supplied Makefiles do not declare all Fortran module dependencies. Use separate checkouts for different toolchains to keep generated sources and objects separate.

4. Configure and run

export ANT=/absolute/path/to/ANT.Gaussian
export OMP_NUM_THREADS=4
export MKL_NUM_THREADS=1
export OMP_DYNAMIC=FALSE
export OMP_STACKSIZE=2G
ulimit -s unlimited

Use the same thread count in Gaussian’s %NProcShared and OMP_NUM_THREADS. The stack setting is a starting point; larger systems may require adjustment.

In the Gaussian input, point both substituted links to the directory containing your newly built executables. For the Intel configuration, for example:

%NProcShared=4
%Subst L101 /absolute/path/to/ANT.Gaussian/bin
%Subst L502 /absolute/path/to/ANT.Gaussian/bin

For the NVIDIA configuration, use /absolute/path/to/ANT.Gaussian/bin/nvidia. Keep the remaining Gaussian input and corresponding .ant file together as described in Input files.

5. Verify the installation

Run a small example from the repository in a separate working directory. Update its %Subst paths, check normal Gaussian termination and the ANT messages in the log, and inspect the expected transmission/DOS output. Compare with an appropriate reference using the same basis, electrode data and numerical settings. Executables already present in a checkout are not evidence of a successful local build.

For compilation failures, inspect Gaussian’s make.log and check compiler compatibility, preprocessor dimensions, integer sizes, library paths and missing interface objects. Rebuild with the selected Makefile after correcting the configuration; do not remove required ABI or OpenMP flags indiscriminately.

Source references: README, installation scripts, Makefiles and configuration, and OpenMP notes. This guide was checked against commit 7dc0b17; a fresh Gaussian build was not performed as part of this documentation update.

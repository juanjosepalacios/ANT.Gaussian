Various options and parameters of the ANT.G code are user-controlled through the job_name.ant input file. This file must be in the same directory as that of the GAUSSIAN03 input file (job_name.com). If there is no parameter file the program will run with the default values, which are given here. The same holds true for an empty file or a file only containing comments and/or blank lines. Remember that job_name; is specified in the title line of the job_name.com or job_name.gjf file, it does not take it from the command line!!.

Syntax rules:
  1. The order of statements is arbitrary.

  2. Comment lines start with the symbol "!".

  3. Empty lines are ignored.

  4. General syntax for real and integer variable assignment:
    KEYWORD = (value)
    where KEYWORD is always in uppercase. All allowed keywords are listed below along with the default value assigned to them.

  5. Logical variable syntax:
    KEYWORD
    If the keyword is specified, the variable is given the value .TRUE. The default value is .FALSE. Thus the logical variables act as switches turning on a specific feature. For example, the keyword MULLIKEN dumps the Mulliken population analysis into a file.

Click a keyword to show its explanation, syntax and default where specified. Click again to collapse it. You can also focus a keyword with Tab and press Enter or Space.

Calculation parameters:

ALPHA (real)

Mixing parameter for the density matrix during self-consistency. The next input density combines the newly calculated density with the previous input density:

P(next) = ALPHA * P(calculated) + (1 - ALPHA) * P(previous)

A smaller value retains more of the previous density and provides stronger damping, which can reduce oscillations but usually requires more SCF cycles. A larger value accepts more of the newly calculated density and may accelerate convergence, but can cause oscillations or instability. Typical starting values are between 0.01 and 0.1. For example, ALPHA = 0.02 mixes 2% of the new density with 98% of the previous density.

When FMIXING is enabled, ALPHA instead controls mixing of the Fock (Kohn-Sham) matrix. NPULAY controls the separate Pulay extrapolation steps. ALPHA is distinct from L1DALPHA, which controls the Dyson self-energy iteration in periodic 1D leads.

Default: ALPHA = 2.0D-2

NPULAY (integer)

DIIS convergence parameter (typically 1 < NPULAY < 10). Every NPULAY normal convergence steps a Pulay extrapolation kicks in.

Pulay extrapolation uses the history of preceding SCF steps to accelerate convergence, whereas ALPHA damps individual updates. If the density oscillates, review both settings rather than changing NPULAY alone. A smaller interval invokes extrapolation more frequently; it does not set an integration tolerance.

Default: NPULAY = 4

LEADBANDS (compatibility keyword)

Periodic 1D leads always find their Fermi levels by band filling; no switch is required. LEADBANDS is accepted for compatibility and has no effect. For each lead independently, solve H(k)c = epsilon S(k)c with all stored couplings through NPC, then fill to NPCEl electrons per chosen repeated cell. ETA gives occupations 1/2 + atan((EF-epsilon)/ETA)/pi, including the full tail from minus infinity. No lower-bound search or Dyson charge integration is performed. The uniform midpoint k mesh doubles from 256 to at most 65536 points. Root charge residual and energy bracket width must meet CHARGEACC and FERMIACC; consecutive meshes must also agree in Fermi energy and in the charge evaluated at the previous mesh's Fermi energy. Failure to converge, or a nonpositive Bloch overlap, stops the calculation. These mesh checks are empirical error estimates. Device density, transmission and optional LEADDOS still use Green-function solvers; ADAPTQUAD affects device contour integration, not the lead band search.

ADAPTQUAD (logical)

Use experimental locally adaptive Gauss-Kronrod quadrature for collinear device density contours. Write ADAPTQUAD on its own line. Only panels with large estimated error are refined; point evaluations are parallel and summed in a fixed order.

PACC controls each device matrix element, with an additional charge-trace check. This can resolve local difficulties hidden by cancellation in total charge. SOC/spinor contours, imaginary-axis and real-axis integration, and device spectral-weight checks retain their existing methods.

The panel limit is 128. Failure to meet the error target stops the calculation. Matrix-panel storage increases memory use for large devices.

Default: .false. (off; legacy quadrature).

BLBRENT and BLSECANT (logical)

Bethe-lattice bulk Fermi levels are found with safeguarded Brent by default (BLBRENT, kept for compatibility). BLSECANT restores the legacy bisection followed by the secant method. Brent stops on a bracket width of FERMIACC; the final charge residual must be below CHARGEACC times the number of electrons per Bethe-lattice atom, otherwise the run stops.

Electrode setup always uses the FERMIACC and CHARGEACC input values, without the staged loosening applied to early device SCF cycles. Both methods print iterations, charge evaluations, residual and wall time.

Default: Brent (BLSECANT absent).

DEVMULLER and DEVBRENT (logical)

By default (DEVMULLER, kept for compatibility) the device Fermi level is found with Muller from the previous Fermi level +/-1 eV, then the secant method, then bisection over the full device interval. DEVBRENT selects safeguarded Brent instead (see BRENT.md). A method falls through when it reaches MAX iterations or leaves the device interval.

Muller and secant use FERMIACC as a relative step tolerance and CHARGEACC*(NCDEl+QEXCESS) as the charge tolerance; bisection stops on a bracket of FERMIACC. Applies to collinear, spin-locked and SOC searches on the contour and imaginary axis. The accepted root is evaluated last and its residual is printed but, unlike Brent, not enforced. Failure of all three methods stops the run.

Brent brackets the root and enforces the final charge residual, at the cost of more charge evaluations per search.

Default: Muller (DEVBRENT absent).

PACC (real)

Numerical integration maximum accuracy for density matrix.

This is the target accuracy for numerical density-matrix integration, distinct from the Gaussian SCF convergence threshold. Smaller values demand better agreement between quadrature estimates and can increase cost. The effective tolerance can be relaxed during early SCF cycles unless FULLACC is present. If the log reports integration failure at the maximum order, lowering PACC alone cannot add more points; the quadrature limit must also be reviewed.

Default: PACC = 1.0D-7

CHARGEACC (real)

Total charge maximum accuracy. For 1D leads, the absolute electron-count tolerance per chosen repeated cell applies both to the band-filling root residual and to the previous Fermi energy's charge residual on a finer k mesh. FERMIACC separately controls energy convergence. No lead charge-contour or integration-bound search is used. Effective tolerances may be relaxed during early SCF cycles unless FULLACC is present.

For the device, the final charge residual must be below CHARGEACC*(NCDEl+QEXCESS), preserving the device relative-charge convention. The safeguarded Brent search evaluates density again at the accepted root and stops if the final residual fails. Root convergence does not establish quadrature accuracy.

The device spectral-weight check on [EMin,EMax] accepts a deviation from twice the number of reduced-device orbitals below min(0.1, CHARGEACC*(NCDEl+QEXCESS)), the same scale as the device Fermi search. It uses the input CHARGEACC, not the value relaxed in early SCF cycles, and converges its quadrature to a tenth of that tolerance. The analytic ETA Lorentzian tail of device states inside the window is added back before comparing; states outside the window are not corrected, so a too-high EMin is still detected and widened. The log prints the tolerance and the tail estimate.

Default: CHARGEACC = 1.0D-5

FERMIACC (real)

Fermi level maximum accuracy (in eV). FERMIACC and CHARGEACC are input targets subject to SCF accuracy adaptation; FULLACC retains input accuracy from the first cycle.

A smaller value requests finer resolution of the Fermi energy and may require more charge evaluations. For 1D leads, it controls the band-filling energy bracket width and agreement of Fermi energies on successive k meshes. CHARGEACC must also be satisfied. The device uses safeguarded Brent with FERMIACC as its shift-bracket tolerance; the printed Fermi energy is the negative shift.

Default: FERMIACC = 1.0D-5

SELFACC (real)

Self-energy accuracy. For 1D leads, tolerance on the mean absolute unmixed Dyson residual, independent of L1DALPHA and not adapted during SCF.

Smaller values require a more accurately converged self-energy and generally more Dyson iterations. For periodic leads, adjust L1DALPHA if iteration is unstable, but use SELFACC to set the required residual accuracy. It is separate from the density-integration and Fermi-search tolerances.

Default: SELFACC = 1.0D-6

L1DALPHA (real)

Mixing parameter for consecutive self-energy matrices in the iterative Dyson solution for 1D leads (0 < L1DALPHA <= 1). Weights the newly calculated self-energy; separate from density mixing ALPHA.

The update is Sigma(next) = L1DALPHA * F(Sigma(previous)) + (1 - L1DALPHA) * Sigma(previous). Smaller values damp updates more strongly, often stabilizing iteration at additional cost. Larger values can be faster but are not optimal for every energy or lead. SELFACC tests the residual before mixing, so changing the mixing weight does not relax that criterion.

Default: L1DALPHA = 0.75

SMALL, SMALLD (real)

Parameters used for the identification of the crystallographic structure of the electrodes and for determining the Bethe lattice directions. The smaller, the more stringent on the atomic structure.  Increase their values if your electrodes are slightly disordered.

These parameters concern geometric recognition, not electronic self-consistency. If lattice directions are identified incorrectly, inspect coordinates and attached branches in the generated XYZ file before loosening the recognition parameters.

Default: SMALL = 0.1

Default: SMALLD = 0.1 (Angstrom)

FULLACC (logical)

Turns on full accuracy from the first cycle.

Write FULLACC on its own line to retain the requested PACC, CHARGEACC and FERMIACC targets from the first lead-enabled SCF cycle. Without it, the code uses looser tolerances at earlier stages to save work. FULLACC can make initial cycles more expensive and does not itself raise the quadrature-point limit.

ETA (real)

Small imaginary part of the Green's function. A value larger than the default may be needed when both electrodes are set to GHOST or when using periodic 1D leads (TYPE1 or TYPE2 = 1DLEAD).

ETA enters the electrode Green's functions (Bethe lattice and 1D leads) and, once, the device Green's function [(z+i*ETA)S-H-Sigma_L-Sigma_R]^-1 (-i*ETA for the advanced function). Every device state is therefore broadened by at least ETA, including states that do not couple to the electrodes. Such a state can then be partially occupied in the device Fermi search instead of producing a jump in the device charge that no Fermi energy can resolve (see QSCAN). ETA does not enter Gamma_L/R, so it does not create spurious transmission channels; GHOST electrodes contribute a zero self-energy.

Increasing ETA smooths narrow spectral structure and can regularize nearly singular inversions, but also changes peak widths and slightly lowers transmission where the electrode coupling is not much larger than ETA. Its Lorentzian tails also move a small amount of spectral weight outside [EMin,EMax]; the spectral-weight check adds this analytic tail back (see CHARGEACC). Check results as ETA is reduced rather than treating smoother curves as proof of convergence. With the default value these effects are negligible.

Default: ETA = 1.0D-10

SL (real)

Convergence criterion for when to switch the infinite electrodes (Bethe lattice) on. These are connected when the standard GAUSSIAN03/09 SCF convergence for the density matrix (RMSDP) reaches RMSDP < SL, where the overall convergence criterion is set in the GAUSSIAN03/09 input file with the SCF option "scf(conver=n)".

Remark: If SL = 0, the leads are only connected after the GAUSSIAN03/09 SCF calculation has converged (cycle=1000). This is only recommended for quick and dirty calculations.

Default: SL = 1.0D-2

FERMISTART (real)

Starting value for Fermi level search (in eV). When reinitializing a calculation from a P.job_name.dat file it is overruled by the existing value in P.job_name;.dat.

Default: FERMISTART = -5.0D0

EFMAX (real)

Upper bound on the device Fermi energy (in eV) during the device Fermi search (DEVBRENT bracket, DEVMULLER Muller/secant acceptance and the bisection fallback). EMin/EMax, the density contours and the spectral-weight check are unchanged. A search whose root lies above EFMAX fails explicitly.

Default: no bound

QSCAN (logical)

Diagnostic. When a DEVBRENT root is rejected because its charge residual exceeds the tolerance, evaluate the device charge residual at 15 Fermi energies from -1 to +1 eV around that root (offsets down to 1.0D-4 eV), log them as QSCAN lines, then stop as before. Costs 15 extra density integrations. A jump that survives this scan marks a discontinuity in the device charge rather than an integration error.

Default: off

SSM (real)

Historical secant-switch threshold. SSM no longer selects the device root algorithm; see DEVMULLER and DEVBRENT.

Default: SSM = 1.0D-3

NATPC1 and NATPC2 (integer)

Number of atoms in the chosen repeated unit of each 1DLEAD electrode. With NPC = 1, choose a unit large enough that hopping and overlap to second-neighbor units are negligible; it may contain several primitive cells. Specify a positive value for each 1D lead. NPC defaults to 1.

For compatibility, NEMBED1/2 are accepted for 1D leads with a warning. If both names are supplied for a lead, their values must agree. Use NEMBED1/2 for Bethe-lattice embedding.

TYPE1 and TYPE2 (string)

Type of model for the semiinfinite electrode. TYPE1 selects electrode 1 and TYPE2 selects electrode 2. Available values are BETHE, 1DLEAD and GHOST.

BETHE: Attach a Bethe-lattice self-energy to the electrode atoms of the input cluster. Select the parameter set for each electrode with BLPAR1 and BLPAR2 (see the BLxxx.dat files).

1DLEAD: Construct a periodic one-dimensional electrode from Hamiltonian and overlap blocks of the input cluster. Include several identical translated repeated units at each end, with a consistent atom order within every unit. List the atoms cell by cell along the wire: electrode 1 is taken from the beginning of the atom list and electrode 2 from the end. Set NATPC1 and NATPC2 to the number of atoms in the chosen repeated unit of each electrode; this unit need not be the smallest crystallographic primitive cell. The two electrodes are extracted independently and need not be identical.

With NPC = 1 (the default), only couplings within a repeated unit and between adjacent units are retained. NATPC1 and NATPC2 must therefore define repeated units large enough that hopping and overlap to second-neighbor units (and beyond) are negligible. Choosing the smallest crystallographic primitive cell will not give a converged lead model if these neglected couplings remain appreciable, even if the Dyson iteration converges numerically. Enlarge the repeated unit by grouping primitive cells and increase NATPC accordingly; check that the lead DOS and transmission no longer change significantly with further enlargement.

Include at least two identical translated copies of the chosen repeated unit at each end so that its Hamiltonian, overlap and coupling to the neighboring unit can be extracted. The outermost NATPC1 and NATPC2 atoms form the lead buffers excluded from reduced-device charge counting. Leave a central device region between these buffers.

For example, NATPC1 = 3, NATPC2 = 3 and NPC = 1 can be used with TYPE1 = 1DLEAD and TYPE2 = 1DLEAD only if a three-atom repeated unit is large enough to make second-neighbor-unit couplings negligible. Otherwise, use a larger repeated unit and increase NATPC1/2. Include at least two copies of that larger unit at each end for parameter extraction. Use the same geometry and atom ordering for corresponding cells. L1DALPHA and SELFACC control the Dyson solution; ETA may need to exceed its default.

GHOST: Attach no electrode self-energy on the selected side. When both electrodes are GHOST, the input cluster is treated as an isolated system, similarly to the original GAUSSIAN03/09 calculation, with ANT.G convergence controls.

Default: TYPE1 = BETHE and TYPE2 = BETHE

BLPAR1 and BLPAR2 (string)

Parameters sets of the Bethe lattice for the first and second electrode, respectively (see available options in files BLxxx.dat).

Default: BLPAR1 = Papacon and BLPAR2 = Papacon

OVERLAP (real)

Factor by which the overlap parameters of the Bethe lattice (when specified in the parameters set) are multiplied (0.0 =< OVERLAP =< 1.0).  When set to a negative value, an automatic procedure to include the overlap (even if not specified in the parameters set) is used. This is the best option although it slows down the calculation with the PGI compiler. Set it to 0.0 for faster calculations and compare. This parameter may need to be smaller than 1.0 to avoid unphysical density of states for the Bethe lattice when the overlap parameters are > 0.2.

Default: OVERLAP = 0.0

GLUE (real)

Factor by which to multiply the selfenergy. Useful to detach in a controled way the system from the Bethe lattice.

A value of 1 retains the model self-energy and 0 removes its contribution. Intermediate values are useful for exploring sensitivity to contact coupling. This changes the physical coupling; it is not an SCF damping parameter and should not be confused with ALPHA.

Default: GLUE = 1.0

NEMBED1 and NEMBED2 (integer)

Number of atoms to be connected to a Bethe lattice branch. These atoms are not taken into account on computing the charge of the system when OVERLAP > 0.

3D Default: NEMBED1 = All atoms in the outermost plane of first electrode and NEMBED2 = All atoms in the outermost plane of second electrode (this is typically a good choice). 2D Default:  NEMBED1 = All atoms in the electrode 1 and NEMBED2 = All atoms in electrode 2 (since you do probably not want this default, you should specify these).

NATOMEL1 and NATOMEL2 (integer)

Number of atoms in first and second electrode. Only useful when the system is composed of a single element or one wants to select especific regions for analysis.

These counts describe the complete explicit electrode regions, not just the boundary atoms attached to a Bethe lattice. For example, an explicit 20-atom tip can have NATOMEL = 20 but NEMBED = 10 when only its outermost ten-atom plane is attached. Keep the counts consistent with the coordinate ordering.

Default: NATOMEL1 = Number of atoms in first metallic electrode and

NATOMEL2 = Number of atoms in second metallic electrode.

FMIXING (logical)

Requests that the damping of the self-consistency be done for the Fock (Kohn-Sham) matrix instead of the density matrix (default). In this case ALPHA refers to the amount of mixing with the newly calculated Fock matrix.

Default: FMIXING = .false.

DMIMAG (logical)

Requests that the density matrix is calculated by integration of the Green's function along the imaginary axis instead of the complex contour (default).

Default: DMIMAG = .false.

Reinitialization options:

When the file P.job_name.dat is present, the calculation is initialized from the density matrix stored in P.job_name.dat. It is advisable to include the keyword nodamp in the SCF options of the GAUSSIAN03 input line "scf=(nodamp)" and make sure that the standard orientation of the system is the same as the one of the density matrix stored in P.job_name.dat. You also need to add "nosymm" to the input file job_name.com as "scf(nodamp,nosymm)" if you want to start with an educated guess for magnetic systems with an unusual spin texture or apply a finite bias voltage. The "nosymm" keyword placed alone on the SCF especifications line (not in the scf brackets) is useful to prevent GAUSSIAN03/09 from rotating the system and is usually necessary for optimizations since GAUSSIAN03/09 likes to change the standard orientation from step to step.

PFIX (logical)

When present, part of a previously computed density matrix can be used.

Syntax:

PFIX

'P.old_job_name.dat'

where 'P.old_job_name.dat' is the file containing the density matrix you want to use. This is useful, .e.g., to change the basis set on a restricted set of atoms while preserving the convergency already achieved in the rest of the system (see NFIX).

Default: .false. (no supplementary matrix provided).

NFIX (integer)

Number of atoms NOT to be touched when using PFIX.

Syntax:

NFIX = N

#atom1, #atom2, ...

where the second line indicates the atoms to be preserved.

The atom numbers refer to the Gaussian input ordering. List exactly the stated number of atoms after NFIX = N. Check that the saved density uses compatible atom and basis ordering; preserving selected atoms does not make an incompatible density matrix transferable.

Bias and gate voltage related parameters:

BIASVOLT (real)

Bias voltage (in eV). It is recommended to perfom first a calculation at zero bias and then reinitialize from P.job_name.dat. Succesive calculations at different bias voltages can be perfomed starting from a previous calculation in the same way. You need to add "nosymm" to the SCF specifications line in  the GAUSSIAN03 input file as "scf(nosymm)". The potential drop profile can be finally read from the file V.job_name.dat where the atom on-site energies (averaged to all orbitals in the atom) are stored.

Default: BIASVOLT = 0.0

QEXCESS (real)

The effect of a gate voltage can be simulated through the addition of positive charges in the GAUSSIAN03/09 input file. To compensate and keep overall charge neutrality, an equal number of electrons should be added. This can be acomplished with this keyword. (Of course one is free to violate charge neutrality if physically required.) It overrules the initial charge given to GAUSSIAN03/09 through its input file, but it is recommended these two quantities to be equal for a more efficient calculation.

Default: QEXCESS = 0.0

Spin related parameters:

SWOFFSPL (real)

Convergence criterion for switching off spin locking in a spin unrestricted calculation (default). Thus in a spin-unrestricted calculation the total spin of the device is kept fixed to the value $(M-1)/2$ given by the multiplicity $M$ in the GAUSSIAN03/09 input file until a certain convergence is reached: RMSDP < SWOFFSPL. (See also NSPINLOCK below)

Advice: SWOFFSPL < SL

Default: SWOFFSPL = 1.0D-3

NSPINLOCK (integer)

Number of steps with spin locking on. It supercedes the SWOFFSPL criterion  when >= 0 (see keyword SWOFFSPL above)

Default: NSPINLOCK = 0.

UD, DU, DD (logical)

Magnetization direction of the Bethe lattice electrodes when these are magnetic. U stands for "up" and and  D for "down". Useful after editing the density matrix to create an educated guess for a new calculation.

Default: .false. (both electrodes "up").

MRSTART (integer)

Useful to create an educated guess for a new calculation with an unusual spin texture starting from a precomputed density matrix. In particular, it reverses the magnetization direction for all atoms with numbers >= MRSTART. You need to add "nosymm" to the SCF specifications line in  the GAUSSIAN03/09 input file as "scf(nosymm)".

Default: MRSTART = 0 (No effect).

SPINDEL (logical)

Erases the spin density of a spin-polarized initial guess in order to achieve a non-magnetic solution, i.e. the initial guess becomes the average of the spin-up and spin-down densities.

Default: SPINDEL = .false.

SPINEDIT (logical)

Useful to create an educated guess for a new calculation with an unusual spin texture starting from a precomputed density matrix. In particular, it manipulates the magnetization direction (spin) of individual atoms. You need to add "nosymm" to the SCF specifications line in  the GAUSSIAN03/09 input file as "scf(nosymm)".

Syntax:

SPINEDIT

#natoms

#atom1, #atomspin1, #atom2, #atomspin2, ...

where #natoms is the number of atoms where the spin is altered. The list below gives the atom numbers and the atom spins for the atoms to be altered where the atom spin can either be maintained (1), reversed (-1), or erased (0).

Default: .false. (off)

NALPHA and NBETA (integer)

Number of alpha (up) and beta (down) electrons. It overrules the numbers determined by the multiplicity given in the GAUSSIAN03/09 input file. Any number is possible as long as it is >= 0. Useful after editing the density matrix to create an educated guess for a new calculation (see SPINEDIT and MRSTART).

Default: NALPHA = NBETA = -1 (not used).

SOC (logical)

Sets a post-SCF spin-orbit coupling calculation. The transmission, polarization, and DOS are computed adding SOC to the solution converged in the absence of SOC.

This evaluates SOC effects using the density converged without SOC. It is useful for comparing transport with and without SOC on the same underlying scalar-relativistic SCF solution. Use SCFSOC when SOC must also feed back into the self-consistent density.

Default: .false.

SCFSOC (logical)

Sets a SCF spin-orbit coupling calculation. The SCF procedure itself includes SOC.

SOC participates in the SCF procedure rather than being added only when evaluating final spectra. This can change the converged density and magnetic state as well as transmission. Converge the SCF solution before comparing it with a post-SCF SOC calculation.

Default: .false.

SOC_FAC_P (real)

Global SOC multiplicative factor for all p orbitals due to lack of nodal structure in basis set. A value of 1.0 gives the exact SOC value as obtained from the integral.

This scales the calculated SOC integrals for the p shells globally. It does not change the basis functions or activate SOC by itself; request SOC or SCFSOC for the corresponding calculation. SOCFACATOM provides site-dependent factors, while a positive SOC_VAL_P replaces the calculated shell coupling rather than scaling it.

Default: 1.0

SOC_FAC_D (real)

Global SOC multiplicative factor for all d orbitals due to lack of nodal structure in basis set. A value of 1.0 gives the exact SOC value as obtained from the integral.

This scales the calculated SOC integrals for the d shells globally. It does not change the basis functions or activate SOC by itself; request SOC or SCFSOC for the corresponding calculation. SOCFACATOM provides site-dependent factors, while a positive SOC_VAL_D replaces the calculated shell coupling rather than scaling it.

Default: 1.0

SOC_FAC_F (real)

Global SOC multiplicative factor for all f orbitals due to lack of nodal structure in basis set. A value of 1.0 gives the exact SOC value as obtained from the integral.

This scales the calculated SOC integrals for the f shells globally. It does not change the basis functions or activate SOC by itself; request SOC or SCFSOC for the corresponding calculation. SOCFACATOM provides site-dependent factors, while a positive SOC_VAL_F replaces the calculated shell coupling rather than scaling it.

Default: 1.0

RCUT (real)

Global cutoff for Yukawa nuclear screened potential.

This controls the screening model used when evaluating atomic SOC integrals. It changes the calculated SOC strength rather than setting a numerical quadrature accuracy. SOCFACATOM allows atom-specific cutoff values when different sites require different screening parameters.

Default: 2.0

SOCFACATOM

Atom-by-atom SOC multiplicative factor and cutoff radius.

Syntax:

SOCFACATOM

#atoms

atom number, soc_fac_p, soc_fac_d, soc_fac_f, rcut

Place the number of selected atoms on the next line, followed by one record per atom: atom_index, p_factor, d_factor, f_factor, cutoff. Indices follow the Gaussian coordinate list. Unlisted atoms inherit the global factors and cutoff in effect when this block is read. Set global values before the atom-specific block.

SOC_VAL_P (real)

Global SOC value for all p orbitals due to lack of nodal structure in the basis set. It uperseeds soc_fac_p if > 0.0.

A positive value supplies the p-shell SOC coupling directly instead of using the screened integral and multiplicative factor. Leaving it at zero retains the integral-based treatment. SOCVALATOM supplies atom-specific shell values; use the same coupling convention when comparing calculations.

Default: 0.0

SOC_VAL_D (real)

Global SOC value for all d orbitals due to lack of nodal structure in basis set. It uperseeds soc_fac_d if > 0.0.

A positive value supplies the d-shell SOC coupling directly instead of using the screened integral and multiplicative factor. Leaving it at zero retains the integral-based treatment. SOCVALATOM supplies atom-specific shell values; use the same coupling convention when comparing calculations.

Default: 0.0

SOC_VAL_F (real)

Global SOC value for all f orbitals due to lack of nodal structure in basis set. It uperseeds soc_fac_f if > 0.0.

A positive value supplies the f-shell SOC coupling directly instead of using the screened integral and multiplicative factor. Leaving it at zero retains the integral-based treatment. SOCVALATOM supplies atom-specific shell values; use the same coupling convention when comparing calculations.

Default: 0.0

SOCVALATOM

Atom-by-atom SOC value and cutoff radius.

Syntax:

SOCVALATOM

#atoms

atom number, soc_val_p, soc_val_d, soc_val_f

Place the atom count on the next line, followed by one record per selected atom: atom_index, p_value, d_value, f_value. Positive shell values replace the corresponding calculated SOC integrals. Unlisted atoms inherit the global SOC_VAL values in effect when the block is read. This input has no cutoff column; use SOCFACATOM for atom-specific cutoffs.

Evaluation parameters

ESTEP (real)

Energy step (in eV) for printing out transmission and DOS.

Choose an energy spacing fine enough to resolve the narrowest spectral features of interest. Reducing ESTEP increases the number of transmission/DOS evaluations and output size. It refines the output energy grid, not the contour integration used to obtain the SCF density.

Default: ESTEP = 1.0D-2

EW1 and EW2 (real)

Define an energy window for printing out transmission and DOS.

The window endpoints are energies in eV relative to the calculation's Fermi reference. Together with ESTEP they determine the sampled transmission/DOS grid. Changing the plotted window does not by itself improve SCF or charge-integration accuracy.

Default: EW1 = -3.0D0 and EW2 = 3.0D0.

DOSENERGY (real)

Energy at which to evaluate the DOS projected on atoms when keyword MULLIKEN on.

Select a single energy in eV relative to the Fermi reference for atom-projected DOS output associated with MULLIKEN. Use it to inspect which atoms contribute at a chosen spectral feature; ESTEP and EW1/EW2 instead control energy-resolved spectra.

Default: 0.0 (Fermi Energy).

LDOS (logical)

Enable energy-resolved local density of states for a selected range of atoms. Both LDOS_BEG and LDOS_END must be explicitly supplied. The endpoints are inclusive, refer to the Gaussian atom ordering, and must satisfy 1 <= LDOS_BEG <= LDOS_END <= number of atoms.

LDOS
LDOS_BEG = 1
LDOS_END = 3

The three lines can appear in any order. Bounds alone do not enable LDOS. With both electrodes present, local DOS is evaluated alongside transmission; with a GHOST electrode, it uses the standalone DOS path. The energy grid uses EW1, EW2 and ESTEP; output is DOS.job_name.dat.

Default: .false. (off).

LDOS_BEG and LDOS_END (integer)

First and last atoms of the inclusive local-DOS range. Both must be explicitly specified when LDOS is enabled; neither bound enables output by itself.

The bounds select a range of atom indices in the Gaussian coordinate ordering. Use a small region to inspect the contact or molecule without output for the full cluster. Check atom numbering after changing the geometry; local DOS remains disabled unless LDOS is present.

Default: LDOS_BEG = 1 and LDOS_END = 0 (LDOS evaluation off).

NCHANNELS (integer)

Number of eigenchannles to print out in T.job_name.dat. If NCHANNELS > 0 then the tranmission matrix (calculated in the non-hermitian or hermitian form, see keyword HTRANSM) is diagonalized and the NCHANNELS largest eigenvalues (i.e. the eigenchannel transmissions) are printed.

Default: NCHANNELS = 0 (eigenchannel calculation off).

LEADDOS (logical)

Prints out the DOS of the Bethe lattice. Output files: Lead1DOS.dat, Lead2DOS.dat

The output also supports periodic 1D leads. It reports bulk-lead DOS, not the local DOS of atoms in the finite device. These files are useful for identifying lead bands and spectral features before interpreting transmission. Enabling the output adds Green-function evaluations and can noticeably increase runtime.

Default: .false. (off).

HTRANSM (logical)

Compute Transmision matrix in hermitian form T = \Gamma_L^{1/2} G^\dagger \Gamma_R G \Gamma_L^{1/2}. The default is the easier non-hermitian form \Gamma_L G^\dagger \Gamma_R G which is considerably faster for large clusters. The diagonalization of both forms yield the same eigenvalues.

Default: .false. (transmission matrix in non-hermitian form).

RTM_BEG and RTM_END (integer)

Perform eigenchannel analysis with reduced transmission matrix [see PRB 73 , 075429 (2006)] on atoms from atom RTM_BEG to atom RTM_END Default: RTM_BEG = 1 and RTM_END = 0 (eigenchannel analysis off).

MULLIKEN (logical)

Dumps the Mulliken population analysis in the file Q.job_name.dat. The DOS projected on atoms at the Fermi energy (or at the energy selected by DOSENERGY) is also dumped when LDOS is enabled.

Default: .false. (not print).

ANT1D (logical)

Requests to write all the necessary input files to be used with the ANT1D transport program.

This exports data for a separate ANT1D workflow. It is not the switch that attaches periodic 1D electrodes during an ANT.G calculation: use TYPE1 = 1DLEAD and TYPE2 = 1DLEAD with NATPC1/2 for that purpose.

Options for electronic correlations

CORRBLOCKS

This keyword specifies a block of atomic orbitals (usually a d- or f-shell of an atom) for further treatment beyond DFT taking into account local electronic correlations.

Syntax:

<num_corrblocks>

<ao_beg> <ao_end> <U> <J>

...

where <num_corrblocks> is the number of correlated blocks within the device region. For each correlated block a line "<ao_beg> <ao_end> <U> <J>" has to be specified where <ao_beg> ist the number of the first atomic orbital and <ao_end> is the last atomic orbital of the correlated block. <U> is the direct Coulomb repulsion and <J> Hund's rule coupling for the correlated block.

DFT+U (logical)

Requests a DFT+U calculation where a Hubbard interaction term (U and J) is put onto each correlated block which is treated within Hartree-Fock.

Define the correlated orbital blocks and their U and J values with CORRBLOCKS. The correction acts on the selected subspaces, so verify the orbital indices and monitor their occupations during self-consistency. Different choices of correlated subspace can change the resulting solution.

HYBFUNC (logical)

Requests the calculation of the hybridization function for each correlated block which serves as an input for an impurity solver calculation. A mesh file "mesh.dat" needs to be present specifiying the energy points for which to calculate the hybridization function.

First define the correlated blocks with CORRBLOCKS and provide mesh.dat in the working directory. The hybridization describes coupling of each selected subspace to its environment and can be passed to an impurity solver; requesting this output does not itself run such a solver.

PORTHO (logical)

Requests to perform a "projective orthogonalization" prior to calculation of the hybridization function. Thereby the device region is orthogonalized in a Gram-Schmidt like manner that preserves the original correlated subspace composed of all correlated blocks.

This is useful when separating correlated orbitals from the rest of a nonorthogonal atomic basis for hybridization analysis. Apply the same subspace and orthogonalization convention when comparing impurity-model inputs across calculations.

DIAGCORRBL (logical)

Prior to calculation of the hybridization function the Hamiltonian of each correlated subspace is diagonalized. This is useful in case of strong crystal-field splitting leading to large off-diagonal elements in the hybridization function. Using this option the crystal-field basis is found, and hence off-diagonal elements of the hybridization function are minimized. This option is also useful in case that the correlated subspace is described by more than one set of orbitals (e.g. double-zeta basis). In this case, the diagonalization yields the low-energy subspace of the correlated shell.
